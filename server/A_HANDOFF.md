## 处理顺序

可信头部 → 语义一致 → AMO 历史键/字节/peer → 新请求解码 → B.handle → 编码并缓存 → 首次回复丢弃或发送 → 每个仍有效的 callback。

AMO 命中直接重放，不再执行业务或生成回调。监控回复是唯一动态字段例外：发送前只读查询原登记剩余时间，不能重新注册。未知/格式/模式/冲突错误不作为业务结果缓存；B 返回的业务失败会缓存。不可识别身份的数据静默丢弃。

ProtocolException 保留原构造函数，仅增加本地可信头和状态访问器以构造安全错误回复。测试用 Sender/时钟注入为包内接口，不改变线上协议或公共构造方式。

## 顺带修复与边界

原 B 分析器 R2 可误接受提前结束的监控日志：现要求有限数字时间戳、结束不早于开始/截止，并增加 3 组回归测试。另加 6 组服务器证据审计测试，防止仅凭客户端最终状态推断执行次数。

没有改写 B 业务或 C 客户端实现。保留他们原有测试和历史证据。最终 200 组测试均通过，16 项网络实验均 PASSED_LOCAL_UDP。

AMO 仅在同一服务器进程历史仍在、同一请求身份及 peer 下成立；不是崩溃持久化或 exactly-once。有限重试耗尽只能表示未知；回调尽力投递。历史无淘汰，长期生产运行需额外容量/持久化设计。
